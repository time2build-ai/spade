The whole idea, once

Project → Tasks → Gates

Agents do the work. A gate is a deliberate pause where Spade waits for your call — nothing ships without you.

🌿 Project→ Tasks→ a kind→ its lifecycle→ you clear gates
✨ Code — build in a worktree → PR → merge 🔬 Research — scope → investigate → report 📄 Docs — outline → draft → shareable doc

Start Spade & connect an account

Part 3 · Fill the board

Where tasks come from

There's no “New task” button on purpose — tasks are grounded in a real source.

🎙️ Meetings
Ingest a transcript (built-in samples included). Each action item becomes a task — with the quote it came from.
💬 Ask
Describe the work in plain language. The orchestrator agent proposes a breakdown — tasks, features, and dependencies — for you to review.
In Ask, try: “Set up a Verde backlog: research the plant-ID approach, a SOW doc, and add a watering-reminder toggle.”
You review before anything runs: the agent turns that one line into 3 tasks + 2 feature nodes with a sensible dependency. It's a proposal from its own reasoning, not pulled from existing data — so you check it, then clear the first gate.

Part 4 · Ship it 🔬

Research — parallel investigators

Scoping→Scope gate→ ▶ N agents→Synthesis→ Review gate→Delivered ✓
Verde task: “Research: on-device plant-ID model vs a third-party API — which fits Verde?” → open it → Start lifecycle.
What happens: you approve the angles at the scope gate → one investigator fans out per angle (card shows ▶ 3 agents) → a manager writes one report → you approve → delivered, with follow-up tasks + brain nodes created. No repo needed.
Part 5 · Ship it 📄

Docs — a shareable deliverable

Outline→Outline gate→ Drafting→Review gate→ Delivered ✓
Verde task: “Write a SOW for the Verde mobile build” → Start lifecycle (“SOW” picks the SOW template automatically).
What happens: approve the outline (cheap to reshape before drafting) → the agent writes a styled, diagram-ready doc → approve → Open document ↗ + Copy share link. A standalone, locked-down page at /api/doc/…, ready to hand the client.
Part 6 · Ship it ✨

Code — worktree → PR → merge

Shaping→Plan gate→ Building→Manual test→ PR review→Merge gate→ Shipped
Verde task: “Add a watering-reminder toggle to Verde's settings”. Needs a repo set in Settings → Repository + gh logged in.
What happens: approve the plan → it builds on a git worktree & runs tests → you do the hands-on manual-test gate → a PR opens & gets reviewed → approve the merge → Shipped to your dev branch. Promote it on Releases.
