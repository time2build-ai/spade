A guided tour

Let’s bring a small app to life
and walk its whole dev lifecycle.

You’ll stand up a real, in-progress project — a link shortener — then move through it the way a team would: a brain full of decisions, a backlog of cards, pipelines mid-flight, a sprint burning down. One command sets the stage; the rest is you, exploring.

① Set the stage ② Plan ③ Build ④ Ship ⑤ Make it move ⑥ Again
Step 0

Set the stage

Make sure the API + UI are running (see the hands-on guide), then run one command.

Bring the app to life In a terminal

This populates a real project — brain, backlog, decisions, pipelines, a sprint — in your live database (~/.spade). No agents, no tokens.

# from apps/api
../../.venv/bin/python -m demo --app link-shortener
You’ll see a summary: “Snip · Link Shortener is live — 6 features · 4 decisions · 11 backlog cards · 6 pipeline runs.”

Pick a different one with --app recipe-box or --app habit-tracker (--list shows all).

Switch into it In the app

Open localhost:3000, click the project switcher (top-left of the sidebar), and choose Snip · Link Shortener.

You’ll see the sidebar fill with the project’s sections. Everything from here on is your project’s real data.
Plan

What the project knows

Before any code, Spade holds the why: features, the decisions that shape them, and the gaps between.

The Product brain Sidebar → Product brain

The rich record of one node at a time — owner, source, the decisions and feedback wired to it.

Try: click around the node list — features like Short-link creation and Click analytics, each with a real owner and provenance.

Decisions (ADRs) Sidebar → Decisions

Four recorded decisions. Three are active; one — “Move analytics to ClickHouse” — is proposed.

Try: use the filter tabs (All / Active / Proposed / Superseded). Open the proposed one to read its full record.

Graph & Issues — the gaps Sidebar → Graph & Issues

The graph on the left; on the right, the issues Spade found by itself from the graph.

You’ll see real findings: an undecided feature (one feature intentionally has no decision yet), orphan nodes, and the unresolved (proposed) decision.
Try: on Product brain, hit Export to MCP — it reports the live node/edge count of this exact graph.

The conflict, waiting at the gate Sidebar → Human gates

Because there’s a proposed decision against an active one, Spade derives a real conflict.

You’ll see the two-panel existing vs proposed — pulled straight from your decision nodes — with Approve / Reject.

Six pipeline runs, each a task moving through developer → reviewer → integrator → documentor.

You’ll see three shipped (100%) and three running at real, mid-stage progress (38% / 62%). Click a row to expand its stage detail, context and live-log.
Ship

Progress, the way a sprint sees it

The dashboards don’t make numbers up — they read your real runs.

Sprints Sidebar → Sprints

The current sprint’s stacked bar and counts are derived from the pipeline runs you just saw.

You’ll see shipped vs in-progress reflect the real runs — ship another (next phase) and these move.

Feedback & Meetings Sidebar → Feedback / Meetings

The inputs that justify the work: two feedback clusters (“Want bulk link import”, “Analytics update too slowly”) with source breakdowns, and the kickoff + analytics-review meetings with their summaries.

Live

Make it move

Everything so far was instant and free. Now hand the wheel to a real agent.

Ask the brain to plan the next feature In the app · ⌘K live agent

First connect an account (once), then open Ask and talk to it:

# connect your logged-in claude (one time)
curl -s 127.0.0.1:8765/accounts/import -H 'content-type: application/json' \
  -d '{"id":"me","label":"My Claude","config_dir":"~/.claude","provider":"claude-code"}'
curl -s -X PUT 127.0.0.1:8765/projects/snip/accounts \
  -H 'content-type: application/json' -d '{"account_ids":["me"]}'

Then ⌘K and ask:

"We have bulk-import feedback. Plan the 'Bulk CSV import' task in 3 steps,
 then say which role should start it."
You’ll see the orchestrator spin up and answer for real — about your project. If it proposes a costly model it pauses at the Human gate for you.

Advance a pipeline yourself In a terminal

Push the analytics dashboard one stage further and watch the Orchestrator + Sprint update on refresh:

# grab a running run's id, then advance it
curl -s '127.0.0.1:8765/pipelines?project_id=snip'
Try: after asking, revisit Orchestrator and Sprints — the picture has moved.
Reset

Start over · try another app

Wipe & re-seed In a terminal

# fresh copy of the same app
../../.venv/bin/python -m demo --app link-shortener --reset

# or a different app entirely
../../.venv/bin/python -m demo --app recipe-box
../../.venv/bin/python -m demo --app habit-tracker
