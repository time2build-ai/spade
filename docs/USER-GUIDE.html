Spade — hands-on guide

Stand up the app, then walk a real project from nothing → planned → executing. Follow the tabs in order.

In the app click in the browser UI In a terminal copy-paste a command Live agent spawns a real claude · costs tokens

Start the app

Two processes: the Python API (the brain + fleet) and the Next.js UI. Leave both running in their own terminal tabs.

1

Start the API In a terminal

Serves everything at 127.0.0.1:8765.

# from the repo root
cd apps/api
../../.venv/bin/python -m uvicorn tui_pilot.server:app --port 8765

You should see uvicorn report “Uvicorn running on http://127.0.0.1:8765”.

2

Start the UI In a terminal

cd apps/client
npm run dev

You should see Next on http://localhost:3000 — open it. You land on the cross-project Home dashboard.

The UI talks to the API through a /api proxy. The commands in this guide call the API directly at 127.0.0.1:8765 (no /api prefix) so you can also drive every feature from the terminal — handy for the parts that don’t have a button yet.

Create a project

A project is the container for everything — its brain, backlog, accounts and pipelines.

1

Open the project switcher In the app

Top-left of the sidebar, click the project name (or “Select a project”). A menu drops down.

2

Fill in “New project”In the app

Enter a Name (e.g. Acme Storefront) and a Path — a real folder on your machine the agents will work in (e.g. ~/code/acme). Submit.

You should see the sidebar switch into the project, and the project pages (Overview, Backlog, Product brain…) light up.

3

Prefer the terminal? In a terminal

Same thing via the API:

curl -s 127.0.0.1:8765/projects -H 'content-type: application/json' \
  -d '{"id":"acme","name":"Acme Storefront","path":"~/code/acme"}'

You should see the created project JSON returned. Confirm it’s listed: curl -s 127.0.0.1:8765/projects

Connect an account

An “account” points at a logged-in claude config dir. The orchestrator (the “Ask the brain” chat) needs at least one to spawn agents.

1

Import your existing login In a terminal

The simplest path: register your already-authenticated ~/.claude dir as an account.

curl -s 127.0.0.1:8765/accounts/import -H 'content-type: application/json' \
  -d '{"id":"me","label":"My Claude","config_dir":"~/.claude","provider":"claude-code"}'

You should see the account appear on the Agent pool page in the UI.

2

Add it to the project’s pool In a terminal

curl -s -X PUT 127.0.0.1:8765/projects/acme/accounts \
  -H 'content-type: application/json' -d '{"account_ids":["me"]}'

You should see the account listed under the project on Agent pool / Accounts.

No ~/.claude yet? Run claude once in a terminal and complete its login, then re-run step 1. (A dedicated “Add account” button in the UI is a known gap — for now this import is the reliable path.)

Ask the brain

This is the real conversational layer — it spins up an orchestrator agent and answers about your project.

1

Open the Ask dock In the app

Press ⌘K (or click the dark “Ask the brain” bubble, bottom-right).

2

Ask something In the app Live agent

Type a real question and send, e.g.:

"What should we work on first to speed up mobile checkout?"

You should see a short “starting orchestrator…” state, then a real answer streamed back. The first ask spawns the orchestrator (takes a few seconds).

This costs tokens. It runs a real claude session against your account. If it says “the project may need a connected account”, finish tab 2 first.
3

Try a planning ask In the app Live agent

Ask it to plan, then to act:

"Plan the work to add a content-based recommender in 3 steps."
"Spawn a developer to start the first step."

You should see a numbered plan; the spawn request appears on the Orchestrator page. If it exceeds the model ceiling it pauses at a Human gate for your approval.

Plan it — decisions, tasks, the brain

Capture knowledge as a graph: features, the decisions that shape them, and the tasks that deliver them.

1

Record a decision (ADR) In the app

Go to Decisions → click “+ New decision” → type a title (e.g. “Lazy-load product carousels”) → Record.

You should see a new ADR row appear with a proposed status pill. Click it to open the full record.

2

Add brain nodes In a terminal

Create a feature and an active decision, and link them:

# a feature
F=$(curl -s 127.0.0.1:8765/brain/nodes -H 'content-type: application/json' \
  -d '{"project_id":"acme","type":"feature","label":"Mobile checkout"}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["id"])')
# an active decision
D=$(curl -s 127.0.0.1:8765/brain/nodes -H 'content-type: application/json' \
  -d '{"project_id":"acme","type":"decision","label":"Use WebP via CDN","status":"active","owner":"You"}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["id"])')
# connect them
curl -s 127.0.0.1:8765/brain/edges -H 'content-type: application/json' \
  -d "{\"project_id\":\"acme\",\"from_id\":\"$F\",\"to_id\":\"$D\"}"

You should see the two nodes on Product brain / Graph & Issues, joined by an edge.

3

Create a task and link it to the feature In a terminal

T=$(curl -s 127.0.0.1:8765/tasks -H 'content-type: application/json' \
  -d '{"project_id":"acme","title":"Optimize mobile checkout","feature":"Checkout"}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["id"])')
curl -s -X PUT 127.0.0.1:8765/tasks/$T/nodes -H 'content-type: application/json' \
  -d "{\"node_ids\":[\"$F\"]}"

You should see the task on the Backlog, linked to the Mobile-checkout feature.

Execute — run the work

A pipeline takes one task through four stages: developer → reviewer → integrator → documentor.

1

Create a pipeline run for the task In a terminal

R=$(curl -s 127.0.0.1:8765/pipelines -H 'content-type: application/json' \
  -d "{\"project_id\":\"acme\",\"task_id\":\"$T\"}" | python3 -c 'import sys,json;print(json.load(sys.stdin)["id"])')
echo $R

You should see a run with 4 queued stages on the Orchestrator page (progress 0%).

2

Start it In a terminal Live agent

Starting stage 0 spawns a real worker agent in the project folder:

curl -s -X POST 127.0.0.1:8765/pipelines/$R/start

You should see the first stage flip to running and the progress bar move. When a stage finishes the pipeline auto-advances; a failure pauses the run for a human.

3

Or drive it from the chat In the app Live agent

Back in Ask the brain, just say what you want — the orchestrator turns it into spawns and gates:

"Run the mobile-checkout task through the pipeline."

Feed it real-world inputs

Meetings, feedback and sprints are first-class — the brain and dashboards react to them.

1

Log a meeting In a terminal

curl -s 127.0.0.1:8765/meetings -H 'content-type: application/json' \
  -d '{"project_id":"acme","title":"Sprint Planning","date":"2026-03-25",
       "summary":"Prioritised mobile checkout.","attendees":["You","Akira"]}'

You should see it on the Meetings page with its summary + attendees.

2

Ingest a meeting → backlog In the app or terminal

A transcript doesn't just get logged — Spade pulls its action items into the backlog. On Meetings, click Ingest a meeting and pick a transcript from a connected source. Or do it over the API:

curl -s 127.0.0.1:8765/meetings/ingest -H 'content-type: application/json' \
  -d '{"project_id":"acme","sample":"todo-kickoff"}'

You should see the meeting land with its summary + transcript, and a Backlog created list of cards — each grounded back to the line that was said. They appear on the Backlog board too. (GET /meetings/samples lists the canned transcripts; pass title + transcript instead of sample to ingest your own.)

3

Add a feedback cluster In a terminal

curl -s 127.0.0.1:8765/feedback -H 'content-type: application/json' \
  -d '{"project_id":"acme","label":"Checkout slow on mobile","count":12,
       "sources":[{"name":"Intercom","n":7,"color":"var(--blue)"}]}'

You should see it on the Feedback page with a source-breakdown bar.

4

Start a sprint In a terminal

curl -s 127.0.0.1:8765/sprints -H 'content-type: application/json' \
  -d '{"project_id":"acme","number":26,"day_label":"day 1/10"}'

You should see the Sprints page show sprint 26 — its shipped/queued counts come straight from your real pipeline runs.

Inspect & export

Ask the brain about itself: what it knows, and where the gaps are.

1

Export the brain to MCP In the app

On Product brain, click “Export to MCP”.

You should see a summary like “Exported N nodes · M edges” — a live manifest of your real graph.

2

Find the gaps In the app

Click “Find gaps” (jumps to Graph & Issues). Or via the API:

curl -s '127.0.0.1:8765/brain/gaps?project_id=acme'

You should see real findings — orphan nodes, features with no linked decision, and unresolved (proposed) decisions. Resolve one by linking a decision (tab 4) and watch it disappear.

3

Check for a decision conflict In a terminal

curl -s '127.0.0.1:8765/gate/conflict?project_id=acme'

You should see a conflict object once you have a proposed decision alongside an active one — the Human gate page renders it as “existing vs proposed”.

Want to see all of this prove out automatically? Run the workflow evaluations: cd apps/api && ../../.venv/bin/python -m evals.run_evals — it drives every workflow above and writes evals/EVALS-REPORT.html.
