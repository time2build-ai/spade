Hands-on workshop · ~15 min

Build a todo app —
by actually using Spade.

You’ll create a small todo app (React front, FastAPI back) yourself, and learn each part of Spade as you go. Nothing is pre-filled — you build it, you watch it appear.

💬 Talk to it — the real way you’d use Spade. Press ⌘K and ask in plain English; its agents do the work. (needs an account · uses tokens)
⌘ Run a command — instant and free. Each step has a copy-paste block. Same result, no agent.
Every command below talks to your running Spade at 127.0.0.1:8765 — start the API + UI first (see the hands-on guide). Use whichever path you like at each step; mix and match.
Step 0

Create the project — your blank canvas

Make a project to hold the app. We’ll call it todo.

⌘ Run
B=127.0.0.1:8765 ; P=todo
curl -s $B/projects -H 'content-type: application/json' \
  -d "{\"id\":\"$P\",\"name\":\"Todo App\",\"path\":\"~/code/todo\"}"
curl -s -X PUT $B/current-project -H 'content-type: application/json' -d "{\"project_id\":\"$P\"}"

Prefer clicking? In the UI, open the project switcher (top-left) → New project → name it, give it a folder.

Open the Backlog (sidebar). It’s empty — four bare columns. That’s your canvas.
Step 1 · Plan

Decide the stack

Record the three architecture decisions that shape the app.

💬 Ask
“Record three active decisions for a todo app: React + Vite for the frontend, FastAPI for the backend, and SQLite via SQLModel.”
⌘ Run
for d in "React + Vite for the frontend" "FastAPI backend" "SQLite via SQLModel"; do
  curl -s $B/brain/nodes -H 'content-type: application/json' \
    -d "{\"project_id\":\"$P\",\"type\":\"decision\",\"label\":\"$d\",\"status\":\"active\",\"owner\":\"You\"}"; done

Or click: Decisions → + New decision, three times.

Open Decisions — your three ADRs, each with an active pill.
Step 2 · Plan

Map the features into the brain

The “product brain” is Spade’s knowledge graph. Add the app’s features as nodes.

💬 Ask
“Add these features to the product brain and link each to a relevant decision: add a todo, complete a todo, edit & delete, filter by status, due dates, persisted storage.”
⌘ Run
for f in "Add a todo" "Complete a todo" "Edit & delete" \
         "Filter by status" "Due dates" "Persisted storage"; do
  curl -s $B/brain/nodes -H 'content-type: application/json' \
    -d "{\"project_id\":\"$P\",\"type\":\"feature\",\"label\":\"$f\",\"owner\":\"You\"}"; done
Open Product brain — your six features, each a real record. Graph & Issues already flags gaps (a feature with no decision yet).
Step 3 · Build

Fill the backlog — back & front

Now the work itself: backend CRUD + the React UI, as backlog cards.

💬 Ask
“Create the backlog for this todo app: a FastAPI backend (SQLite schema, POST/GET/PATCH/DELETE /api/todos with a status filter) and a React frontend (list view, add-todo form, complete toggle, filter tabs, due-date picker). Tag each with its feature.”
⌘ Run
add(){ curl -s $B/tasks -H 'content-type: application/json' \
  -d "{\"project_id\":\"$P\",\"title\":\"$1\",\"feature\":\"$2\",\"priority\":$3}" >/dev/null; }
# backend
add "SQLite schema + SQLModel models"        "Persisted storage" 0
add "POST /api/todos — create"               "Add a todo"        1
add "GET /api/todos — list + status filter"  "Filter by status"  1
add "PATCH /api/todos/:id — toggle & edit"   "Complete a todo"   1
add "DELETE /api/todos/:id"                  "Edit & delete"     2
# frontend
add "Todo list view"                         "Add a todo"        1
add "Add-todo input form"                    "Add a todo"        1
add "Complete toggle + strikethrough"        "Complete a todo"   1
add "Filter tabs (All / Active / Done)"      "Filter by status"  2
add "Due-date picker"                        "Due dates"         2
echo "backlog ready ✓"
Open Backlog — ten cards in Ready, each tagged with its feature. Click one to see its detail. (screenshot shows the finished app, with cards moved across columns)
Step 4 · Build

Put an agent on a task

Run one task through the 4-stage pipeline (developer → reviewer → integrator → documentor).

💬 Ask live agent

Connect an account once (below), then:

“Run the ‘POST /api/todos — create’ task through the pipeline.”

Spade spawns a real developer agent in your project folder and tracks it on the Orchestrator.

⌘ Run — free, no agent
# grab a task id from your backlog
curl -s "$B/tasks?project_id=$P" | python3 -c "import sys,json
for t in json.load(sys.stdin)['tasks'][:4]: print(t['id'], t['title'])"
# run it through all 4 stages instantly (fake spawn)
# NOTE: this helper writes in-process — point it at your server's data dir:
TUI_PILOT_HOME=~/spade-qa ../../.venv/bin/python -m demo --advance SPD-002 --project todo --to shipped
Open Orchestrator — your run, moving through its stages. Sprints updates too: its counts come from these real runs.
Step 5 · Inspect

See what Spade noticed

It reasons over your graph — for free.

Open Graph & Issues — it flags the undecided feature and (if you added the proposed “user accounts” decision) an unresolved decision. Resolve one by linking a decision and watch it disappear.
That’s the loop

Now do it for real — just talk to it live agent

You’ve seen every surface. Day to day, you don’t curl — you ask. Connect an account once:

curl -s $B/accounts/import -H 'content-type: application/json' \
  -d '{"id":"me","label":"My Claude","config_dir":"~/.claude"}'
curl -s -X PUT $B/projects/todo/accounts -H 'content-type: application/json' -d '{"account_ids":["me"]}'

Then ⌘K and try:

“Add a ‘dark mode’ feature, record a decision to use CSS variables for theming, and create a frontend task for it.”

Watch the brain and backlog update — the agent did it, for your project.
