A · Polished node-link

evolve, don't replace

Keep the graph, make it intentional. Bigger pill-nodes carrying a type icon + label inline (no more floating text), node size scales with how connected it is (importance at a glance), curved gradient edges, and a soft type-colored halo. Hovering lifts a node and dims the rest; selection highlights its direct links.

Strengths

  • Familiar; least migration risk
  • Importance & type readable without clicking
  • Looks like a deliberate product, not debug output

Watch-outs

  • Still a graph — gets busy past ~30 nodes
  • Needs decent layout (degree-weighted / force)

B · Clustered constellation

structure-first

Group by type into soft territories. Each type gets a translucent hull (a region) so the picture reads as "here's the features, here's the decisions, here's what users said." Edges that cross regions are the interesting ones and draw brighter. Great for spotting which decisions back which features at a glance.

Strengths

  • Instant sense of make-up (lots of bugs? few decisions?)
  • Cross-type links pop — the real insight
  • Scales better; clusters absorb density

Watch-outs

  • More layout logic (hulls, packing)
  • Less precise for tracing one long chain

C · Readable board

PM-friendly · recommended start

Drop the hairball for the default view. A graph is pretty but a non-technical PM (the test-guide audience) reads a grouped list far faster. Columns by type, each a stack of titled cards with a link count. Click a card → the info panel shows its relations (and we can still offer the graph as a "Map" toggle for power users).

Strengths

  • Most legible; zero graph-reading skill needed
  • Scales to hundreds of items (just scrolls)
  • Title + type + count is all visible upfront

Watch-outs

  • Loses the "shape" of how things interconnect
  • Best paired with a graph toggle, not as sole view
