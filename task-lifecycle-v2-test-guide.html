Track A

👀 Quick visual tour EASY · ~5 min

Just start the app and look at the new screens. Nothing can break. No GitHub repo needed.

  1. Open your terminal and start the app.

    cd /Users/thiagolopez/time2build/projects/tui-pilot/.claude/worktrees/task-lifecycle-v2 make dev
    You should see: two servers boot. It will print UI → http://127.0.0.1:8766. Leave this terminal running.

  2. Open http://localhost:8766 in your browser, then click Backlog in the left menu.

    You should see: the board now has 6 columns instead of 4:
    ReadyShaping Plan reviewBuilding PR reviewShipped
    The two amber columns (Plan review, PR review) are the ones waiting on you.

  3. In the left menu under PLAN, click the new Releases item.

    You should see: a page with three lanes — Development, Staging, Production — with a Promote button between them. (Lanes may be empty until a task ships — that's fine.)

  4. Click Settings in the left menu and scroll to the Repository section.

    You should see: input boxes for Repo SSH URL and the three branch names (development / staging / main), plus a Save repository button.

  5. Go back to Backlog and click any task card to open it.

    You should see: the task page. When a task is running the lifecycle it will show an Artifacts area (Spec / Plan / Test guide / Review) and, when it's your turn, a gate bar with Approve / Request changes buttons. On a fresh task you'll instead see a Start lifecycle button.
✅ That's Track A. If all five boxes are ticked, the new screens are wired up. If you're happy here, you can stop — tell Claude "Track A looks good". Only continue to Track B if you want to watch a real task run end-to-end.

Track B

🚀 Drive a real task, start to finish DEEP · 20–40 min

Configure a throwaway GitHub repo, then watch a task go brainstorm → plan → you approve → build → you test → PR → review → you approve merge → shipped.

Before you start, you need three things: (1) a throwaway GitHub repo you don't mind Claude pushing to, with a development branch; (2) gh logged in (gh auth status); (3) at least one Claude account in the Agent pool. If any is missing, tell Claude and it'll help you set it up.

  1. In Settings → Repository, paste your throwaway repo's SSH URL (e.g. git@github.com:you/scratch.git) and click Save repository.

    You should see: the save button confirm. This is what lets a task leave the Ready column.

  2. Open a task in Ready and click Start lifecycle.

    You should see: the task move to Shaping. Behind the scenes an agent is now brainstorming + writing a spec and a plan in its own worktree. Give it a few minutes.

  3. Wait for the task to land in Plan review (amber). Open it.

    You should see: a Spec and a Plan in the Artifacts area, and a gate bar asking you to approve the plan. Read the plan. Click Approve (or Request changes with a note to send it back).

  4. The task moves to Building. Wait for it to turn amber again (the manual-test gate).

    You should see: a new Test guide artifact — a simple, numbered "click this, you should see that" checklist the agent wrote for you. Follow it to try the change yourself.

  5. Happy with your hands-on test? Click Approve on the manual-test gate.

    You should see: the task move to PR review. A real Pull Request is opened on your GitHub repo, and a reviewer agent posts findings as PR comments, then applies fixes.

  6. Open the task once it reaches the merge gate. Read the review findings + fixes summary, then click Approve merge.

    You should see: the branch merged into development, the task move to Shipped, and a dev badge light up on its card.

  7. Go to Releases. Your task should now be in the Development lane. Click Promote to open a development→staging PR.

    You should see: an auto-written release note listing the task(s) being promoted, and a real PR opened on GitHub. Merge it yourself, and the task's staging badge lights up.
🎉 All done. If a task made it from Ready all the way to a Release with you approving the three gates, the whole feature works end-to-end. If anything stalled or a task landed in a red Blocked banner, open it — the activity notes explain exactly what happened — and tell Claude.
