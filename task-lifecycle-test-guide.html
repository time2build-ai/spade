🧭 Three kinds of task

The router reads each task's title + description and suggests a kind. Each kind runs its own lifecycle:

✨ Code — brainstorm → build in a worktree → PR → merge (needs a repo) 🔬 Research — scope → parallel investigators → synthesis → report (no repo) 📄 Docs — outline → draft → shareable styled document (no repo)

Track C · 🔬 Research

Watch parallel research + synthesis MEDIUM · no repo

A research task splits into angles, runs investigators in parallel, and a manager synthesizes one report. Needs a Claude account in the Agent pool — no GitHub repo.

  1. Create a task like "Research: how does our auth flow work?" (or a general one). Confirm the router's 🔬 Research suggestion (or set it), then click Start.

    You should see: it starts with no repo required and lands in Planning (scoping).

  2. Wait for the Scope gate (amber). Open the task and read the proposed research plan (the angles). Approve it (or request changes).

    You should see: a plan artifact listing N angles; approving fans out one investigator per angle. The card shows ▶ N agents while they run.

  3. Let the investigators finish. A research manager then synthesizes them. Wait for the Review gate.

    You should see: per-angle findings grouped under a final report on the task. Read the report; approve to deliver.

  4. Confirm delivery.

    You should see: the task moves to Done → delivered ✓, with the report + findings pinned, and any proposed follow-up tasks / brain nodes created.

Track D · 📄 Docs

Produce a client deliverable MEDIUM · no repo

A docs task drafts a styled, shareable document (SOW or Explainer) with diagrams. Needs an agent account — no repo.

  1. Create "Write a SOW for the Q3 mobile project". Confirm 📄 Docs (the router also suggests the template — SOW vs Explainer). Click Start.

    You should see: it starts (no repo) and lands in Planning (outline).

  2. Wait for the Outline gate. Review the section structure and approve (or request changes — saves rework before the full draft).

    You should see: an outline artifact for the chosen template; approving moves it to drafting.

  3. Let it draft, then hit the Review gate. Open the doc artifact — it renders as a styled document (with diagrams).

    You should see: a polished, theme-aware document in a preview, plus "Open document ↗" and a share link. Approve to deliver.

  4. Open the share link in a new tab.

    You should see: the standalone styled document at /api/doc/… — hand-to-a-client ready, and safe (locked, no scripts). Task is delivered ✓.

Track B · ✨ Code

Drive a code task start-to-finish DEEP · needs a repo

The full brainstorm → worktree build → test → PR → review → merge → ship flow.

Needs first: a throwaway GitHub repo with a development branch, gh logged in, and a Claude account in the pool. Set the repo in Settings → Repository. If any is missing, tell Claude.

  1. Create a small code task (e.g. "Add a dark-mode toggle"), confirm ✨ Code, set the repo, and Start.

    You should see: it enters Planning (shaping: brainstorm → spec → plan) in its own worktree.

  2. Approve the Plan gate → let it build → do the hands-on Manual-test gate (follow its test guide) → approve.

    You should see: spec + plan + a kid-simple test guide as artifacts; the task moves through Building → PR review.

  3. A PR opens on GitHub; review findings + fixes are applied. Approve the Merge gate.

    You should see: the branch merges to development, task → Shipped with a dev badge. Promote it on the Releases page to reach staging.
🎉 All done. If a task of each kind reached its terminal state with you clearing the gates, the whole thing works. If any task landed in a red Blocked banner, open it — the activity notes explain exactly what happened — and tell Claude.
